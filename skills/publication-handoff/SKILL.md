# 发布交接

使用当前选定的内容版本和用户指定的渠道、账号、受众及时间。已批准内容只做必要交付检查，不自动重写。缺少发布连接时可完成文件/文本交付，不伪造可执行工具或账号状态。

## 交付内容

按渠道需要提供：正文/主题与版本、媒体引用、变量、链接/追踪参数、目标账号或受众引用、计划时间与时区、审批依据、仍需补齐的字段。只有真实对象存在时附上工作台 ID。

核对文件可访问、媒体用途、最终文案和链接；邮件交接补充分群/订阅资格由谁核实、变量缺失如何处理及测试状态。不因为产品档案已确认就推定所有内容和受众已批准。

## 执行与恢复

先检查现有工具/API 实际能力和当前授权。`ContentSchedule` 是排期记录，创建或同步它不等于发到了社媒或邮箱。Magpie/MCP 尚不能由技能正文自行变成可用服务。

实际提交后保存可用的请求/批次 ID 和状态。网络超时后先查询是否已接受，避免盲目重复发送；无法确认时报告待核实状态并停止重发。只有可用的幂等机制才使用，不假设每个渠道都有幂等键。

交付报告区分草稿、已排期、服务已接受、已发布/已送达和失败。只声称本次真正完成并能举证的状态，附影响后续动作的缺口。未执行的建议不会自动成为已创建的工作台记录。
