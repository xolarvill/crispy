# 品牌与产品上下文

先确认店铺、产品和本次更新范围，读取已有且获准使用的产品资料与用户决定。局部改一个参数时，只处理该参数及受影响表述，不重开品牌定位访谈。

## 建立可引用的知识

按用途整理，而不是将所有记忆拼接成一段提示词：

- 产品事实：型号、适用场景、规格、价格/优惠的有效期、售卖地区、交付条件。
- 定位决定：目标客户、主要需求、替代选择、价值主张；标明是谁确认及适用范围。
- 表达依据：品牌语气、真实样例、可使用的证据、需要避免的无依据表述。

重要主张附资料路径或 URL、观察日期和适用产品；保留“已确认事实 / 研究推断 / 建议变更”的身份。缺失的性能、认证、销量和客户评价不能用常识补齐。

## 变更与冲突

现行用户决定优先于过时草稿。两份有效资料冲突时，列明冲突字段和各自来源，继续完成无关部分；询问会改变当前交付的关键事实。不要把“取最新时间”当作判断所有事实真实性的规则。

输出面向本次任务的上下文或变更清单：字段、当前值、建议值、依据、确认状态。只有获得相应授权才写入长期知识；未经确认的研究不覆盖品牌事实。数据库记录更新前核实当前接口和 shop 归属，不直接用 SQL 批量替换记忆。

## 完成判断

另一位执行者能识别哪些卖点可直接引用、哪些仍待确认，且能追溯原始依据。若只是整理事实，不额外生成季度营销计划或品牌口号。
