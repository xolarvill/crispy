# 视频素材编辑：统一框架与首期边界

日期：2026-11-17。状态：首期基础编辑已实现于功能分支，尚待用户体验反馈。使用与验证边界见 [video-editor.md](../video-editor.md)。

视频编辑属于 crispy 的素材创作与编辑框架。用户和 agent 在 crispy 内操作同一份工程；基础能力通过包装好的 MCP 工具提供，同时可供 UI、HTTP 和进程内阶段调用。OpenMotion 是技术参考和可选择性复用的来源，不作为产品层、工程权威或独立工作台直接接入。

## 当前基础

以下记录设计开始时的基础。新增实现：`VideoProject` / `VideoRevision` / `VideoRender`、服务端中立时间线与源素材固定、共享编辑服务、Twick 时间线与原生媒体预览、`videowright` MCP、本地 FFmpeg 导出及素材回流。后续专业软件适配与通用 DAG 调度不在本次范围内。

- `app/schemas/boards.py` 定义服务端权威的 `BoardScene`；tldraw 是文档的编辑视图。视频素材目前作为 asset 节点展示，没有时间线文档。
- `app/services/board_tools.py` 的类型化工具目录被阶段工具、HTTP 和 `app/mcp/boardwright.py` 共用。一次工具 pass 可提交为一份可撤销的白板 revision。
- 素材目前主要由 `Artifact`、`VariantAsset` 及文件 URI 承载。`app/services/run_media.py` 聚合现有输入与产物；尚没有统一的跨媒体编辑工程与不可变素材版本系统。
- 当前白板 agent 工具保护人工节点，并不允许任意修改人工内容。视频工程的授权编辑规则需要单独定义，不能通过复用白板工具取消这项保护。
- 白板的阶段执行与任意 DAG 调度仍有独立边界，见 [instruction-board.md](instruction-board.md)。增加时间线不会自动实现通用节点执行引擎。

## 框架归属

```text
用户 UI / 外部 agent MCP / 进程内阶段
                  ↓
       crispy 类型化素材编辑服务
       工程身份、revision、操作、历史、任务
                  ↓
       媒体专用文档和执行适配器
       图片 / 文字 / 视频时间线
                  ↓
       预览、检查、渲染及结果入库
                  ↓
       crispy 素材、白板与下游阶段
```

共用身份、来源、版本引用和任务语义，不强迫图片、文字、视频使用同一份编辑文档。白板文档管理空间布局、指令与关系；视频文档管理时间、轨道与片段。两者通过明确的工程/素材引用连接，避免把时间线塞进 tldraw store，或让一次画布移动改变剪辑。

## 首期基础能力

| 能力 | 首期范围 |
| --- | --- |
| 素材接入 | 选择现有视频、图片、文字及音频，读取真实时长、画幅、帧率等元数据 |
| 时间线 | 视频/图片片段顺序排列，文字叠加轨和基础音频轨；播放头、缩放与吸附 |
| 视频剪辑 | 设置素材入出点、切分、删除、移动/重排片段；剪辑保持非破坏性 |
| 基础合成 | 设置输出画幅，素材适配画幅，基础文字样式，音频静音与音量 |
| 人机协作 | 人工与 agent 使用同一套编辑操作；冲突检查、批量操作、撤销重做、保存重开 |
| 观察 | 读取结构化时间线、指定时间点取帧、预览指定区间；返回具体 revision 和时间码 |
| 导出 | 本地 MP4 后台任务、进度/失败/取消、固定输入快照、基础技术验证和成片入库 |

首期不纳入高级动效、复杂转场、调色、跟踪、蒙版、自动内容理解/选段，也不纳入 OpenMotion 的完整模板库、品牌库、模型网关和独立 agent 管理。首期不接入 PR、DaVinci Resolve、After Effects；这些是后续执行适配器的候选。

## 最小数据与操作契约（拟议）

- **工程**：稳定 project ID、归属 workspace、输入素材引用、当前文档 revision；与单次 run 分离，允许 run 引用它。
- **时间线文档**：schema version、输出尺寸与有理数帧率、轨道、稳定 clip ID、素材引用、素材入出点、时间线位置、文字/画面适配与音量参数。固定时间精度和帧对齐规则，避免浮点累积。
- **输入固定**：编辑/导出不能只依赖可被覆盖的 URI。先为现有素材建立解析与固定引用机制，可使用文件内容指纹及不可变副本；不要求首期重写全部历史素材模型。
- **修改**：操作带 project ID、expected revision、actor 和重试身份。批量操作原子提交为一个可撤销 revision；重试不重复插入片段。人工或 agent 更新后，旧 revision 写入明确失败。
- **历史**：撤销/恢复创建可追踪的新状态，保留来源和后续历史；不覆盖原始素材。视频工程的 history 与白板 history 分开，通过引用关联。
- **导出任务**：绑定确定文档 revision 和输入快照，保存状态、进度、失败原因、输出 URI、规格与校验结果。导出后即使工程继续编辑，也不改变已交付成片。

MCP 是服务的薄包装，不把业务逻辑放进工具入口。候选工具职责为读取工程/素材、读取时间线、应用类型化操作批次、取帧/预览、历史恢复和请求/查询/取消渲染。名称与参数在实现时确定，本文不表示工具已注册。是否扩展 `boardwright` 或新增素材 MCP 入口属于传输层选择；不能再建一份编辑状态或业务实现。

agent 对用户授权的工程可执行剪辑，但不得借此修改白板中的人工指令。工具要表达明确动作，例如保留素材 A 的 1–4 秒、在时间线第 2 秒切分、修改某段文字，而非让 agent 任意改第三方工程文件。

## UI 与白板

用户从现有视频素材入口进入 crispy 内的预览与基础时间线。白板可引用编辑工程及其固定版本，也可引用渲染结果；复杂编辑操作在时间线中完成，白板继续负责素材与任务之间的关系。

素材被编辑不应静默替换所有历史 run 使用的文件。新的成片作为衍生产物入库，记录源素材、工程和 revision；下游明确选择新产物，或由已有运行语义触发更新。

## 第三方复用与后续扩展

OpenMotion / Hyperframes 的共享人工与 agent 工程、revision 冲突保护、切分时素材入点处理和固定快照导出值得参考。可按模块评估代码或组件复用，但 crispy 保持自己的文档和服务契约，保留所用第三方许可证与来源。Twick 也仅作为基础编辑组件候选；现有实验不构成底座定案。

未来 PR、DaVinci、AE 的连接放在执行适配器层，复用素材身份、操作意图、任务状态与产物回收。各工具声明实际能力与工程格式；专用效果可使用对应的原生工程引用，不假设所有效果都能无损翻译成首期时间线。超出能力的请求明确报告，不静默丢弃。

## 实现顺序与验收

1. **文档与服务**：定义时间线契约、素材固定引用、类型化操作、revision 和历史。先验证入出点/切分、重试、冲突及原始素材保持不变。
2. **基础编辑 UI 与 MCP**：在现有素材入口增加预览和时间线，两种入口调用同一服务。验证人工剪辑 → agent 读到新状态 → agent 修改 → 人撤销/重做 → 保存重开。
3. **本地渲染与回流**：固定快照导出、校验、成片入库与白板/阶段引用。验证带音频素材、切分前后取帧、非整数帧率、失败和取消；媒体预览须支持 Range。

每层独立验证后提交，不以安装某个 SDK 作为功能完成标志。完整验收至少包括两段素材的截取与重排、图片/文字叠加、音轨编辑、人机接续、旧版本拒写、保存恢复、MP4 导出与结果回流。长视频/高分辨率性能需另行测量。

## 本轮参考证据

2026-11-17 的隔离验证已跑通 OpenMotion 的本地导入、素材入点、人工切分/撤销/重做、agent 接续改字、版本冲突保护、保存重开与 4 秒带音频导出；75 项针对性测试通过。发现其成片下载端点不支持 Range，Blob 播放正常；本机 C 盘空间不足时需要把安装和渲染临时目录切至 D 盘。这些是候选实现的验证结果，不代表 crispy 已实现上述能力，也不是长期负载验证。
