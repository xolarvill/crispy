# Marketing workbench：工作覆盖、协作边界与上游 vendor

更新日期：2026-11-01。本文合并保存上游 vendor 调研、用户调整后的工作覆盖与优先级，以及页面边界、人和 agent 分工、首版范围的讨论建议。未安装上游 skills、未接通发送/发布，也未改变现有运行时。

目标：与 agent 协作的 marketing all-in-one workbench，首批聚焦社媒和 EDM，再扩展广告、转化、社区与营销分析。参照本地独立项目 `D:\CODING\seo-workbench` 的方法融合模式；该项目位于 crispy 仓库之外。

## 决策状态与阅读顺序

- **用户给出的方向**：四个分区及下面逐项标注的首版需要、后续扩展、待讨论、暂不纳入；从原店铺记忆中拆出品牌与产品知识、市场与客户研究；活动策划作为任务专线。
- **待讨论的建议**：具体独立页面、页面内视图、工作流入口、人和 agent 的操作分工，以及下方首版交付范围。保存本轮讨论不代表这些建议已全部获批。
- **候选 vendor**：供后续比较与适配，没有最终锁定供应来源、导入版本或执行服务。先明确工作覆盖与边界，再吸收 skills。

本文后半部分的上游能力优先级来自前期选型；如与用户本轮的范围冲突，以用户本轮范围为准。例如活动策划属于后续扩展，实验与知识积累暂不纳入独立模块。

## 页面边界建议（待确认）

| 分区 | 页面或能力 | 建议边界 |
| --- | --- | --- |
| 记忆与知识 | 品牌与产品 | 独立页面；保存已确认的产品知识、定位、语气、卖点、证据和禁用表述，供任务引用 |
| 记忆与知识 | 市场与客户研究 | 独立页面；研究任务、来源、发现和待确认判断；确认采用后进入长期知识 |
| 记忆与知识 | 公共基础 | 分别进入知识、素材、任务、数据和连接设置；通过对象关系共享，不另建包罗全部的页面 |
| 记忆与知识 | 营销目标与规划 | 后续扩展；首版在具体任务中记录目标、受众和衡量方式 |
| 生产 | 内容与创意 | 独立页面；围绕任务组织输入、草稿、素材、版本和交付物 |
| 生产 | 审阅与质量控制 | 放在内容详情中，围绕具体版本修改、评论与批准；有规模后再增加集中待审视图 |
| 数据 | 效果分析 | 独立页面；比较内容、渠道、活动表现，并支持形成下一步任务 |
| 数据 | 转化分析 | 效果分析内的视图；诊断访问→订阅/询盘→购买等路径，页面或表单修改转为生产任务 |
| 数据 | 社区、口碑与客户倡导 | 后续拆分：评论评价是研究输入，案例/UGC 是资产，社区经营是工作流 |
| 工作流 | 渠道工作流 | 统一方法/模板入口；渠道之间共享任务与内容对象，避免重复任务系统 |
| 工作流 | 发布与排期 | 作为候选独立视图，查看准备发布、待处理与已执行内容；是否首版接通尚待确认 |
| 工作流 | 生命周期经营 | 建议先支持邮件序列设计与交付；持续事件监听和自动发送后续再做，整体优先级仍待讨论 |
| 工作流 | 活动策划 | 关联多个任务的活动方案，后续增强跨任务管理；不新增同名侧栏页面 |
| 工作流 | 实验与知识积累 | 不建立独立模块；已有分析结论和经人工确认的经验可以保留 |

知识与研究的边界：前者回答“我们已经确认什么”，后者回答“发现了什么、依据是什么、还需确认什么”。研究结果不自动覆盖品牌定位。

候选导航：记忆与知识下设“品牌与产品、市场与客户研究”；生产下设“内容与创意”；数据下设“效果分析”（含转化分析）；工作流下设“渠道工作流、发布与排期”；设置承载店铺与渠道连接。该导航是讨论建议，不是已经实施的界面。

尚待确定：工作流页面是模板入口还是日常任务中心。当前建议将日常任务留在生产区域，工作流用于选择社媒、EDM 等方法并创建任务。内容与创意承载产物编辑，发布与排期跟踪对外执行，同一个任务关联这些视图。

## 人与 agent 的分工建议（待确认）

| 工作 | 人负责 | Agent 负责 |
| --- | --- | --- |
| 品牌与产品知识 | 确认事实、定位、语气与边界 | 整理材料、发现冲突、提出补充与修改建议 |
| 市场研究 | 决定研究问题、确认重要判断 | 搜集证据、比较来源、归纳发现、更新研究 |
| 内容生产 | 给目标、提供经验、修改与选择 | 拟定方案、写作制作、适配渠道和生成变体 |
| 审阅 | 对具体版本反馈与批准 | 检查事实依据、品牌、格式和链接，执行修正 |
| 发布 | 确定账号、受众、时间和授权范围 | 按授权执行、记录回执、处理可恢复失败 |
| 数据分析 | 提供业务背景、选择下一步行动 | 汇总数据、发现变化、提出解释与行动建议 |

人可以直接编辑产物，agent 从同一版本继续工作。聊天、编辑器、任务记录指向同一份成果；人修改了优惠条件等事实后，后续标题、邮件和衍生内容都应使用新版本。能力是否通过 Magpie、MCP 或现有 runtime 执行，不改变这一协作边界。

## 首版交付范围建议（待确认）

以下收敛用户标记为首版需要的能力，并明确哪些闭环能力仍需要讨论：

1. **知识可用**：维护品牌、产品和证据，供研究和生产任务引用。
2. **研究可继续**：发起研究、查看来源、补充判断，将确认后的发现写入知识。
3. **社媒与 EDM 可生产**：首批聚焦社媒内容批次、邮件和邮件序列，统一草稿、素材与版本；图片、视频、文章和落地页仍属于整体覆盖，不代表首版新增所有编辑器和发布服务。
4. **审阅可完成（待讨论项的建议）**：在内容详情中修改、反馈和批准。
5. **发布可交付（待讨论项的建议）**：排期、状态记录、选定渠道的发送/发布路径；其他渠道可导出。具体平台和连接方式未定。
6. **数据可指导行动**：导入或同步已有数据，查看内容效果、转化路径，并创建后续任务；不承诺首版完成所有来源连接或完整多触点归因。

季度/年度规划、完整跨渠道活动管理、社区经营与倡导仍是后续扩展。完整 CRM、持续触发生命周期自动化及独立实验平台不作为本轮首版承诺。转化诊断可以提出验证建议，不等于建设已暂不纳入的实验模块。

## 本地 SEO workbench 的参照依据

已读取相邻项目的 `README.md`、`skills/README.md`、`docs/skill-sources.md`、`docs/skill-sources.json`、`docs/agent-skill-routing-design.md` 与维护验收记录。该项目的来源清单登记了 60 个一级技能入口、409 个受维护文件，主要来源是 SuperSEO、Claude SEO、SEO Machine，另有本地适配方法；这里引用的是清单记录，未重新运行其验收。

它的核心做法是：按用户任务组织方法索引；agent 根据目标、现有决定、产物和证据选择、组合方法；保留上游身份、固定比较版本、文件指纹、许可证及本地修改历史。固定比较版本不冒充原始导入版本。该项目已经退役 `next` 阶段调度，专业交付按证据和结果验收。

其中已有 `social-content`、`email-sequence`、`paid-ads`、`launch-strategy` 等本地适配技能。Marketing 实施前应逐项比较这些材料与下方新候选，优先复用适用的方法及适配经验，同时保留真实来源与本地派生关系；本轮未复制文件，也未改动 SEO workbench。

因此，下文的活动闭环是典型使用场景，实施顺序是工程依赖顺序，均不要求每项营销任务走固定阶段。局部改帖、修改邮件或分析数据可以直接进入对应方法；现有且适用的研究与草稿应继续使用。

## 你提到的 commerce-agents

[anthropics/commerce-agents](https://github.com/anthropics/commerce-agents) 是官方购物助手与商家后台助手的参考蓝图，约 3.4k Stars，Apache-2.0。它与电商营销有交集，但主要处理购物与商家业务。README 明确说明它是 **不持续维护、不接受贡献的参考实现**。

对 crispy 最有价值的借鉴是：agent 定义、工具契约、人工审批与应用执行的边界。它的商家写操作先暂存、再由人确认；演示并未真正下单、扣款或修改在线商品。建议作为架构参考。直接匹配营销工作的官方来源是上表中的 Marketing 插件。

## 如何融合进 crispy

以下是产品与工程建议，尚未实现。

1. **共享上下文先行。** 每个 workspace 保存品牌语气、产品、受众、证据、禁用表述和渠道偏好；每个 campaign 保存目标、时间、预算与指标。将这些字段组装成上游期望的上下文，减少每个 skill 重新访谈。
2. **以活动贯穿工作。** 活动简报连接社媒帖文、视频、邮件和落地页任务；任务里可与 agent 讨论、修改并保留版本。沿用现有任务、素材、发布、数据和记忆区域，导航是否新增由实际工作流决定。
3. **Skills 输出结构化草稿。** 明确输入与交付物类型，让表格、日历、邮件预览和审阅页可直接使用；记录上游来源、版本和执行事件。`SKILL.md`、persona、工具服务分别适配，不把它们视为同一格式。
4. **执行由连接器完成。** 草稿进入发布计划后，再交给邮件或社媒服务。UI 分别显示待审批、已排期、执行中、服务已接受和失败；发送 API 接受不等于送达，日历有条目也不等于已经发布。
5. **审批绑定内容版本。** 人修改正文、受众或发送时间后重新检查审批有效性。发送记录使用幂等标识，异步回执关联到具体内容，避免重试造成重复发送。
6. **结果回到活动。** 保留 campaign/content ID、UTM、渠道回执和观察窗口。复盘结论进入可审阅记忆，区分来源事实、推断与建议。

### 社媒 MVP

路径：活动简报 → 一周内容批次 → 人工编辑/品牌审阅 → 排期 → 发布或导出 → 结果回收。

先让一个目标平台完成闭环，再增加平台。第一版同时支持文案和素材包导出，连接状态明确可见。候选 skills 覆盖多个平台，并不证明 crispy 已拥有对应平台的发布权限。

### EDM MVP

路径：活动与受众 → 邮件序列 → 模板预览 → 测试邮件 → 审批/排期 → 发送 → 退订、退信和转化结果。

需要补充联系人/受众分群、订阅状态、抑制名单、模板版本、发送批次及事件记录。名单来源和可发送状态进入数据契约。外部 EDM 平台可负责维护名单；crispy 保存引用和任务所需快照，避免第一版复制完整 CRM。

电商品牌可优先验证 Klaviyo 连接，通用 newsletter 可评估 Mailchimp/Brevo，自建邮件路径可评估 Resend。这是待验证的产品选型建议，尚未比较账户成本、地区可用性与 API 覆盖。Cold outreach 应作为独立用例，当前 EDM 首批聚焦已有订阅/客户关系。

### 与现有代码的衔接

现有 `Campaign`、`VariantAsset`、`ContentSchedule`、`AgentTraceEvent`、`GmMemory` 可作为活动关联、创意素材、排期、执行记录和学习的基础。需逐项评估 schema，不能假定其当前字段已支持跨渠道内容或邮件流程。

建议增加的基础能力是 skill 来源注册与版本锁定、统一上下文组装和输出校验。邮件任务不应为了复用现有机制而被强行转换成图像/视频 pipeline。Magpie/MCP 按 README 既定方向接入；本轮未实现 gateway 或插件。

## 实施顺序与验收

| 层次 | 必要工作 | 验收依据 |
| --- | --- | --- |
| 1. 来源与契约 | 选定首批 skills，逐个审阅正文、脚本和引用；锁定 commit；保留许可与归属；定义输入输出 | 相同品牌上下文可生成可编辑的活动、帖文和邮件草稿；每项可追溯来源 |
| 2. 协作与审核 | 品牌/活动上下文、内容版本、人工编辑、预览、版本对应的审阅 | 人能从简报一路修改并审阅完整交付物 |
| 3. 社媒闭环 | 一个渠道的授权、排期、发布、状态回收与导出 | 实际发布回执可追踪，失败可恢复且不重复发布 |
| 4. EDM 闭环 | 一个邮件服务、受众引用、订阅/抑制状态、测试发送和批次事件 | 测试与正式发送区分清楚；可观察退信/退订并避免重复发送 |
| 5. 复盘扩展 | 指标导入、实验与归因、审核后的经验沉淀 | 报告能回指原内容、数据来源和时间范围 |

每层完成后单独提交。评测应使用同一份真实品牌 brief：比较品牌一致性、事实准确性、人工修改量及交付物可用性。当前结果是来源选型，不是营销效果排名，也不是完成集成的声明。
